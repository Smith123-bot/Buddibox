- No `ANDROID_HOME`, `ANDROID_SDK_ROOT`, adb, Android emulator, Java/JDK, local Gradle executable or EAS CLI was detected. No connected device could be queried without adb. There is no generated `android/` native project or EAS project link. A local Gradle Android build is not currently feasible; cloud EAS build needs an Expo account/project configuration, credentials and network access to Expo services not available in this environment.
- `app.json`: name **BuddhiBox**, scheme `buddhibox`, version `0.1.0`, portrait, dark UI, Android ID candidate `com.buddhibox.app`, `versionCode: 1`. App ID ownership/availability unverified. Minimum and target Android API levels are **not pinned or verified**: the actual native Gradle output and Play policy compliance must be inspected during a real build. Only `expo-router` config plugin is declared.
- Offline introspection of the Expo Android manifest shows default `INTERNET` and `VIBRATE` permissions. INTERNET is framework-provided; gameplay does not request network content. `SYSTEM_ALERT_WINDOW`, `READ_EXTERNAL_STORAGE` and `WRITE_EXTERNAL_STORAGE` now have `tools:node=remove` directives via `android.blockedPermissions`; verify the final merged release manifest before claiming they are absent. Dev tools may require overlay permission in development builds; verify that profile separately. No new gameplay permission was added.
- `eas.json` documents internal APK (`preview`) and Play-oriented AAB (`production`) profiles, plus development APK. This is **configuration only**, not an executed or validated EAS build. Do not commit keystores/secrets. Version code must increment for any later uploaded build.

## 2. Brand and bundled assets

The initial Expo template icon/splash were inspected and were unrelated blue/gray placeholder graphics. They have been replaced with original BuddhiBox “B” artwork in the dark-purple, teal and gold palette: `assets/icon.png` (1024² opaque), `assets/android-icon-foreground.png` and `android-icon-monochrome.png` (1024² transparent), `assets/splash-icon.png` (512² transparent). Source `/usr/share/fonts/truetype/dejavu/DejaVuSans-Bold.ttf`, DejaVu/Bitstream Vera license in `/usr/share/doc/fonts-dejavu-core/copyright`. Verify artwork/attribution in release policy review. Unused template `android-icon-background.png` and `favicon.png` remain in the repository but are not referenced by `app.json`; no useful work was deleted.

## 4. Build and device-test instructions (not executed here)

1. Install Android SDK/emulator and supported JDK according to the selected Expo SDK documentation, or provide a USB-debuggable Android device with `adb`. Verify `adb devices`, Java version, SDK platforms/build-tools and the actual app build environment. No global toolchain installation was performed during this audit.
2. `cd mobile && npm ci && npm run check && EXPO_OFFLINE=1 npx expo export --platform android`. This validates code and bundled JS only. For local native development build, set SDK/JDK paths then use `npx expo run:android`; inspect generated Gradle SDK levels and final merged permissions. Do **not** confuse this with a signed release build.
3. For cloud signing, use an Expo account and install/use `npx eas-cli@latest`. Confirm ownership of `com.buddhibox.app`, configure the EAS project and signing outside Git. Internal APK command: `npx eas-cli@latest build --platform android --profile preview`. Production AAB command, only after release approval: `npx eas-cli@latest build --platform android --profile production`. The workspace cannot reach Expo/EAS service in this session; neither command was run here. Confirm the real output artifact exists, signature/variant, package ID, API levels and permissions before distributing. Do not publish in this phase.
4. Install the actual internal APK on at least two Android sizes (one narrow/low-end), run full three-game playthrough and Hindi corpus review with TalkBack and large fonts, record build hash, device, OS, video/screenshots and defect results. Test process death, app background, lock/unlock, rapid taps, offline fresh install and upgrade from a signed prior version preserving progress. Verify no P0/P1 defects before considering release.

## 5. Outstanding blockers

- **Critical:** no Android hardware/emulator and no installable signed build have been tested; min/target SDK and merged manifest remain unknown.
- **Critical:** Hindi rendering and accessibility on Android are unverified, including conjunct/matra clipping.
- **High:** Find the Difference art/gameplay lacks independent on-device visual QA; only three of the larger launch target pairs exist.
- **High:** `npm audit --omit=dev` currently reports 47 advisories (26 moderate, 21 high). Review direct/transitive exposure and remediations without blindly upgrading Expo SDK packages; investigate production artifact composition before release. Expo Doctor's two external checks remain blocked by network.
- **High:** AsyncStorage is not transactional, and corrupt/future-version saves are now protected from silent overwrites but lack in-app recovery/export. Interrupted multi-key achievement writes are retried on next screen focus but not device-verified.
- **Medium:** no production privacy policy/Play listing, asset-license sign-off, Play content rating/age classification, crash monitoring plan, real size/performance measurements, or signing ownership decisions. App ID is provisional. Daily Challenge, drag Word Search, sound and full Hindi UI are not implemented; do not advertise them.

**No release sign-off.** Treat this as configuration preparation and static/automated QA, not Android certification.
