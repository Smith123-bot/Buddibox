# BuddhiBox Phase 8 — feature and integration audit

**Later level expansion:** [Phase 10 status](PHASE10_EXPANSION_STATUS.md) contains current counts: 3 Difference scenes, 100 Maze routes, 10 Word Search puzzles. The inventory below documents the Phase 8 historical snapshot.

**Later update:** [Phase 9 UI/reliability review](PHASE9_UI_RELIABILITY.md) adds a non-finite Difference-tap guard, wrapping play metrics and storage-write regression coverage; the Phase 8 test figures below remain its historical baseline, not the latest total.

**19 October 2026.** Static/code and automated integration audit, not Android-device certification. Baseline after restoring locked dependencies with `npm ci`: TypeScript and lint passed; **68 tests in 21 suites passed**. Final results are recorded below. No Git operations, native build, APK/AAB or Android device/emulator test occurred in this phase.

## Inventory (verified from implementation)

- **Navigation:** Expo Router root stack and four tabs (Home, Games, Progress, Profile); `/` redirects to tabs. Stack destinations: game details `/games/[id]`, scene/route/puzzle selectors and play routes under `/difference`, `/maze`, `/word-search`, Settings, About and an unknown-route fallback. Stack header provides back on detail/play screens; selectors provide return controls where implemented. Android system/predictive back and unmount checkpoint behavior require device testing.
- **Home/Games:** Home shows three catalog-backed playable games, real saved-session Continue controls for each, a persisted-achievement highlight and real completion counts. Games cards open details, then corresponding selectors. The hero's daily wording is motivational; there is no Daily Challenge. Loading, no-progress, unknown-game/route and storage-error paths exist.
- **Find the Difference:** `garden-001`, `harbor-002`, `market-003` (three 900×600 local image pairs, five mapped changes each). Selector unlocks sequentially on a preceding completion. Two tappable image panels map contained touches to normalized ellipses; repeated taps do not score, misses count (first three free), two hints per attempt outline uncompleted targets. Accessible object list includes real targets and decoys. Active-time par bonus, pause/background checkpoints, restart/replay, completion result, best/attempt record and resumable save are implemented. Pixel-region verification is encoded in the artwork generator; actual visual difficulty, hit accuracy, zoom (not implemented) and TalkBack remain unverified on Android.
- **Maze Escape:** eight fixed seeded DFS-generated routes `path-001`…`path-008` (4×4 through 9×9), with shortest BFS path lengths **8, 11, 14, 17, 22, 30, 32, 42 moves**. Validation checks boundaries, symmetric passages, connectivity and exit reachability. Four direction buttons block illegal moves; three BFS next-step hints, active timer, optimal-move/time score, pause/restart/replay, sequential unlocking and local save/continue are implemented. The board is RN views, not image assets.
- **Word Search:** ten compiled boards, five English (`en-001`…`en-005`) and five Hindi (`hi-001`…`hi-005`), each with **three targets**, for 30 shipped target words. English packs: Garden words, Sky watch, At the shore, In motion, Nature trail. Hindi packs: बगीचा, देश, प्रकृति, आसपास, शब्द. The build tool uses Node/ICU grapheme segmentation and NFC at content-generation time; the bundled JSON stores per-cell tokens and placement paths. Runtime uses the compiled grapheme arrays (not UTF-16 slicing or Hermes segmentation). Corpus tests cover matras/conjunct examples, bounds, unique placement and conflicts. Select two endpoints by touch (forward/reverse, straight or diagonal); no drag gesture. Two hints point to a target's first cell, scoring counts completed words plus active-time bonus minus hints. Timer, pause/restart/replay, independent language unlocks and local saved session are implemented. Linguistic suitability and glyph shaping/pronunciation have **not** been independently verified by Hindi readers on Android.
- **Shared UI:** AppText, EmptyState, GameCard, PrimaryButton, ScreenContainer, SectionHeader, SurfaceCard, design tokens, DifferencePanel, MazeBoard and WordGrid. Word grid has horizontal scrolling and 48 dp cells; small-screen layout and screen-reader focus need device tests. No external font is bundled; local PNG launcher/splash/adaptive artwork plus three Difference pairs are shipped. Unused template background/favicon remain but are not referenced by app config.
- **Progress/Profile/Settings:** pure `aggregate` computes per-game and overall real distinct clears, total clears, attempts, unlocks, best scores, dated completions and recorded hint/effort metadata. Profile identifies a local player without an account. Six stable achievements: FIRST_WIN, PUZZLE_EXPLORER, MAZE_MASTER, WORD_FINDER, DIFFERENCE_DETECTIVE, NO_HINTS; thresholds/progress are derived from verified clears/events, and grant timestamps persist on first observation. Settings persists the only functional preference, game-card haptics; About is reachable from Settings. No cloud sync, sound toggle, leaderboards, nickname editor, daily reward or invented session dates.
- **Persistence:** existing version-1 AsyncStorage keys for Difference, Maze and Word Search, plus a separate achievements key and haptics-preference key. Stores serialize same-key writes in process, validate known IDs/records, preserve legacy clears without synthesizing events, deduplicate run IDs and reject corrupt/unsupported game-save JSON instead of overwriting it. AsyncStorage is not transactional; achievements can be reconciled on a later screen focus after a failed separate write. There is no in-app save repair/export or cloud backup.
- **Tests/docs/tooling:** 21 baseline Jest suites cover game engines, corpus/Unicode, storage, screen routes/components, progress, Android config and safe-save paths. Scripts: `start`, `android` (Expo development server), `typecheck`, `lint`, `test`, `check`. Config: strict TS, Jest Expo, ESLint Expo, Expo Router in `app.json`, package lock, and EAS development/preview APK and production AAB profiles. README, blueprint, game/content notes, progress guide and Android release-readiness report are present locally. `mobile/node_modules` is intentionally ignored; dependencies were restored from the lockfile for this audit.

## Bugs found and actions

1. **Fixed:** About falsely said gameplay, saved progress and achievements were not implemented. It now describes the actual three offline games and device-local progress; added a screen regression test.
2. **Fixed:** Home showed a first-clear empty-state sentence while local progress was still loading or unreadable. The footer now distinguishes loading, read failure and genuine no-clear state; extended its screen test.
3. **Fixed documentation:** Word Search notes still said achievements were not implemented; updated them to point to shared achievements. README implied launcher/splash were template artwork although Phase 7 replaced them.
4. **Open/requires device or product decision:** Hindi shaping/word editorial review, real image target/touch accuracy, TalkBack and large text, system/predictive back, timer/process death, and incomplete-save recovery/export. No safe static claim of a hardware fix is made. No visible gameplay controls were found that are deliberately wired to no action; native interactions still need device verification.

## Release and build limitations

Existing `eas.json` preview is configured for an internal APK; it has not been executed. `app.json` retains `com.buddhibox.app`, versionCode 1, and has no EAS project ID. The current workspace cannot reach Expo services and has no Android SDK/adb/JDK, signing configuration or APK. Android-targeted **JavaScript export is only a bundle check**, not a native build. Review production security advisories and the Phase 7 release-readiness report before distribution; follow it with a real signed build, merged-manifest/SDK inspection, Hindi and accessibility device QA, installation/upgrade and offline save testing. No extra content, cloud project, dependencies or signing secrets were added here.
